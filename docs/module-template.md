# 模块文档模板（v3 讲义 + 施工双标准）

> v3 修订（2026-08-18）：根据项目主人要求，每篇模块文档必须是**两本书合一**——
> ① **课本/讲义**：事无巨细，定义、大白话、例子齐全，学生能自学能举一反三；
> ② **新手施工指南**：明确到"写哪个文件、哪个函数、它干什么（伪代码描述作用）"，学生照着亲手写出真代码。
> 所有 23 篇按此标准逐步升级。

```markdown
| 代码落点 | backend/agent_godot/xxx/（N 个文件，见 §0.5） |
| 前置模块 | … |
| 手写比例 | … |
| 教程映射 | … |

## 0. 本模块在项目中的位置
【大白话开场：用生活类比说清"这是干嘛的、为什么需要它"；
  交付后状态（验收 Demo 预告）；结构图（mermaid/text）】

## 0.5 ★ 施工文件清单（开工前必看的一页表）
| 新建文件（完整路径） | 职责一句话 | 关键类/函数 | 预估行数 | 手敲步骤(§4) | 依赖 |
（+ 文件依赖顺序：谁先写谁后写、为什么）
（+ "完成后你拥有什么"清单：能跑的命令/能过的测试）

## 1. 知识点详解（每小节五段式）
### 1.x 知识点名
**① 严格定义**：教科书式一句话（含公式/术语，可考试作答）
**② 大白话**：生活类比讲透"为什么需要它、它解决什么痛点"
**③ 举例**：具体数字/场景完整走一遍（能算的必须代数字手算）
**④ 演进史**：时间线 + 每代解决上一代什么问题 + 例子
**⑤ 易错点**：实战坑清单（每条：现象→根因→防法）

## 2. 接口设计（完整签名 = 你要手写的契约）
每个类/函数配一行大白话注释（"它是干嘛的"）。
签名齐全 + 类型齐全，实现留白手写。

## 3. 关键难点参考片段
全模块最难的一段给出可参考的实现级代码 + "为什么难"。

## 4. 手敲指引（函数级伪代码 ★施工核心）
每一步：
- 写哪个文件、含哪些函数
- 每个函数的作用用【伪代码/文字算法】描述：先做什么后做什么、
  边界条件是什么、返回什么——学生看懂伪代码后自己写真代码
- 验证命令/单测：写完立刻跑

## 5. 测试与验收
可直接粘贴的 pytest 用例 + 终端验收 Demo 命令。

## 6. 踩坑记录（留白自填）
| 日期 | 坑 | 现象 | 根因 | 解法 | 关联知识点 |

## 7. 面试拷打（★每题必须附详细参考答案）
10 题，每题答案 3~10 行：结论 + 展开理由 + 本项目对应实现，
标准是"面试可口述 3 分钟"。

## 8. 教程映射与延伸
教程代号引用 + 必读/选读论文文档。
```

## 写作铁律

1. **凡概念必有类比**：抽象概念（协议/熔断/缓存…）先给生活对应物
2. **凡公式必代数字**：手算一遍才算讲清
3. **凡演进必讲痛点**：每一代存在的原因 = 上一代的死穴
4. **凡施工必到函数**：文件→函数→伪代码作用→验证，四级齐全
5. **凡提问必有答案**：面试拷打不允许留白
6. **与已学内容互相引用**："你在 M01 实验/上一轮对话里见过…" 帮学生连线
