## 0. 本计划在项目中的位置

**大白话**：截至 M12，代码里已经散落着 **13 个文件的硬编码 prompt**（intent 分类、查询改写、HyDE、压缩摘要、记忆抽取、权限确认文案……），再加上各处的魔法数（阈值/超时/预算/开关）。这就像**把菜谱刻在灶台上**——想换个口味（调 prompt、换小模型、关个功能）就得拆灶台（改代码、重启、甚至重新提交 git）。本计划要做的是：**把菜谱抄到菜谱架（config/）上，灶台只留火候默认值**——改菜谱不动灶台，改配置不改代码。

回答立项之问："是不是可以在 config/ 的配置文件中添加可自由配置的配置项？"——**是，且这正是既定路线**：M00 目录树早已预留 `config/settings.yaml`，models.yaml 的 providers/routing/embedding 三节已经跑通了"yaml 可选覆盖 + 代码默认值兜底"的模式（`ModelRegistry.route()` 未配置回落 ask 就是范例）。本计划把这个模式**制度化、全覆盖**。

**交付后状态**：改 prompt 不改代码；换小模型只动 yaml；功能开关（联网搜索/语义缓存/记忆抽取/HyDE…）一键启停；新环境零配置可跑（全部默认值）；密钥只存在于 .env。

```text
优先级（高 → 低）：环境变量 > config/*.yaml > 代码内默认值
                     └── 三层兜底：任何一层缺失都能从下一层拿到值
```

## 1. 设计原则（六条铁律）

### 1.1 三层优先级：env > yaml > 代码默认值

| 层 | 载体 | 放什么 | 生命周期 |
|---|---|---|---|
| L1 环境变量 | `.env` / 系统 env | **密钥**、部署环境差异（端口/DB 地址）、CI 临时覆盖 | 部署时定 |
| L2 配置文件 | `config/*.yaml` | **用户日常可调项**：prompt 模板、模型路由、开关、阈值、预算 | 随时可改（热加载见 §6） |
| L3 代码默认值 | 各模块常量 / Settings dataclass | **兜底**：删掉 yaml 里任何一项，系统照常跑 | 发版时定 |

**大白话**：L3 是"出厂设置"，L2 是"用户设置"，L1 是"工厂 override"——电视机没有遥控器（yaml 被删）也该能看（默认值），产线测试（CI）想临时换个台不用改遥控器（env 直接注入）。

### 1.2 默认值纪律：代码里必须有，且是唯一事实源

- 每个可配置项在代码里有一个**带默认值的声明**（dataclass 字段 / 函数签名默认参数），文档以它为准；
- yaml 里**只写想覆盖的项**——半份配置文件是合法的（models.yaml 的 routing 已如此：只写 ask 其余回落）；
- **禁止**"yaml 没配就崩"——缺配即用默认值 + 一条 warning 日志（`ModelRegistry._resolve_key()` 对本地服务的处理是范例）。

### 1.3 什么外置、什么不外置（判断口诀）

| 外置（用户可能想调） | 不外置（改了必坏，留在代码） |
|---|---|
| 所有发给 LLM 的 **prompt 模板**（占位符用 `{var}`） | 协议常量（JSON-RPC 字段名/SSE 事件 type） |
| 模型选择与采样参数（temperature/max_tokens） | 数据结构（dataclass 字段名/Schema） |
| 功能**开关**（联网/缓存/HyDE/记忆抽取） | 内部状态机转移规则 |
| 量化**旋钮**（阈值/TopK/截断长度/预算上限） | 与正确性强相关的安全逻辑（如 deny 优先级） |
| 超时/重试次数/路径（Godot 可执行文件位置） | 密钥本体（只进 .env，永不进 yaml/git） |

**判断口诀**：问自己"用户调这一项，是**调偏好**还是**改行为语义**？"——偏好外置，语义留守。语义类若真要可调，走 ADR 而不是配置。

### 1.4 密钥与配置分离（沿用 models.yaml 纪律）

yaml 只写 `api_key_env`（环境变量名），密钥本体在 `.env`（.gitignore 已排除）。扩展到新配置文件时同理：**settings.yaml / prompts.yaml 永远可以进 git，因为它们不含秘密**。

### 1.5 配置是数据不是代码

- prompt 模板放 yaml，**不放 Python 常量再"导出"**——避免两处维护；
- 模板渲染用 `str.format_map()`（禁 `str.format()` 裸调用，占位符缺失时报 KeyError 要转成缺省文案）；
- 配置校验放加载期（fail-fast：类型错/引用不存在的 provider 立刻报），不放使用期。

### 1.6 消费者无感

所有改造不改变任何函数签名（新增参数一律带默认值）——CLI/Web/Bench 三个消费者零改动（M00 铁律 1 的延续）。

## 2. 配置面全景（config/ 目录最终形态）

```text
config/
├─ models.yaml        # 已有：providers / routing（含任务角色）/ embedding
├─ mcp.yaml           # 已有：MCP 服务器注册表
├─ permissions.yaml   # 已有：权限规则
├─ settings.yaml      # ★ 本计划新增：开关/旋钮/路径/预算（M00 目录树预留位）
└─ prompts.yaml       # ★ 本计划新增：全部 LLM prompt 模板
```

### 2.1 settings.yaml（功能开关与运行参数）

```yaml
# ============================================================
# settings.yaml —— 运行行为配置（均可缺省：缺一项用一项代码默认值）
# ============================================================

godot:
  executable: godot            # headless 可执行文件（PATH 名或绝对路径）
  timeout: 120                  # headless 单次运行超时（秒）

context:                        # M07 上下文工程
  max_tokens: 32000             # 上下文预算
  observation_truncate: 4000    # 单条工具结果截断长度
  compress_trigger: 0.85        # 触发压缩的水位线（占预算比例）

cache:
  semantic_enabled: true        # M02 语义缓存总开关
  exact_enabled: true

query_engine:                   # M12
  web_search_enabled: false     # 联网搜索开关（产品设置里的那个）
  hyde_enabled: false            # HyDE 假想文档（可选，贵）
  intent_cache_size: 128
  rewrite_history_turns: 3      # 改写时回看的对话轮数
  web:
    max_results: 5              # 每次搜索取前 N 条
    fetch_timeout: 15

memory:                         # M08
  extract_enabled: true         # 会话结束记忆抽取开关
  max_items_per_session: 20

rag:                            # M10
  top_k: 8
  rerank_enabled: false
  chunk_size: 512
  citation_enabled: true

agent:                          # M03 预算熔断
  max_steps: 40
  budget_tokens: 200000
  budget_usd: 1.0
  tool_timeout: 60
```

### 2.2 prompts.yaml（prompt 模板库）

按模块分节，键名与代码内默认模板**一一对应**——代码里的常量叫什么名，yaml 节就叫什么名（可对账、可 grep）：

```yaml
# ============================================================
# prompts.yaml —— LLM 提示词模板（占位符用 {name}，运行时注入）
# 缺省任意一节 = 用代码内默认模板（见各模块 *_PROMPT 常量）
# ============================================================

query_engine:
  intent: |
    判断用户输入的意图，只输出标签：
    code_edit=修改/创建项目代码 | knowledge=询问 Godot/引擎知识 | ...
    （与 intent.py 中 INTENT_PROMPT 默认值一致）
  rewrite: |
    把口语追问改写为独立完整的问题。历史：{history}
    追问：{query}
    只输出改写后的问题。
  hyde: |
    针对问题写一段假想的完美答案（不必真实）：{query}

context:
  compress: |
    把以下对话历史压缩成要点清单，保留工具调用与结论：{history}

memory:
  extract: |
    从会话记录中抽取值得长期记住的项目约定与事实：{transcript}

permission:
  confirm_write: "将写入 {path}（{risk} 风险），允许吗？"
```

> **纪律**：prompts.yaml 是"调优区"不是"改语义区"——改坏了 prompt 属于用户自己的操作，系统只保证**缺省可用**。因此每个模板键在代码里必须有同内容默认值（§1.2）。

## 3. 代码侧契约：统一加载器 `core/settings.py`

### 3.1 接口设计（完整签名）

```python
# backend/agent_godot/core/settings.py —— 三层配置加载器（env > yaml > 默认值）

@dataclass
class Settings:
    """全量运行配置的运行时镜像（字段=默认值=文档）。

    每个子节一个嵌套 dataclass；yaml 里同名键覆盖字段值；
    环境变量 AGENT_GODOT__<节>__<键>=<值> 覆盖 yaml（双层下划线分隔）。
    """

    @classmethod
    def load(cls, config_dir: str | Path | None = None) -> "Settings":
        """工厂：找 config/ 目录，settings.yaml 与 prompts.yaml 可选存在。
        步骤：dataclass 默认值 → yaml 覆盖（存在的节/键）→ env 覆盖 →
        类型校验（pydantic 式，错则 fail-fast）。"""

    def prompt(self, section: str, key: str, **vars: Any) -> str:
        """取模板并渲染：prompts.yaml 有则用之，否则回落代码默认模板。
        占位符缺失 → 保留 {var} 原样并 warning（不崩，§1.5）。"""

    def get(self, dotted: str, default: Any = None) -> Any:
        """点路径取值：settings.get('rag.top_k', 8)。供轻量消费者。"""

# 模块级单例（懒加载，进程一个）：
def get_settings() -> Settings: ...

# prompt 默认值仍定义在各模块内（唯一事实源），
# 通过 prompt() 的回落机制生效——settings 不复制默认值，只引用。
```

### 3.2 与既有 `ModelRegistry` 的关系

- `ModelRegistry` 继续管 models.yaml（职责单一：谁接模型谁用它）；
- `Settings` 管 settings.yaml + prompts.yaml；
- 二者**并列不合并**——settings 里 `cache.semantic_enabled=false` 只是把总开关关掉，embedding 节仍在 models.yaml（度量衡不跟开关走）；
- 后续若出现交叉需求（如"按租户配额"，M19），在 app 层做配置聚合，核心包两个加载器保持不变。

### 3.3 改造范式（每个模块两行搞定）

```python
# 改造前（M12 intent.py 现状）：
resp = await llm.chat(INTENT_PROMPT, ...)          # 硬编码常量

# 改造后：
from ..core.settings import get_settings
resp = await llm.chat(get_settings().prompt("query_engine", "intent"), ...)
# 用户没配 prompts.yaml → 拿到的就是 INTENT_PROMPT 默认值，行为不变
```

开关与旋钮同理：`if get_settings().get("query_engine.hyde_enabled", False):`。

## 6. 热加载与会话一致性（沿用 M00 §12 Q9 结论）

settings/prompts 的热加载**不做**（M13+ 再议），理由：

1. prompt 变更影响的是**新轮次**而非运行中请求——重启 CLI 成本近零；
2. Web 应用端（M19）若要热加载，直接复用 models.yaml 的三件套方案（config_version 快照 + 引用计数 + 变更通知），不在本计划重复设计；
3. 本计划范围内只保证**进程启动时加载一次、失败 fail-fast**——简单可测。

## 7. 测试与验收（P1 用例，可直接粘贴）

```python
# backend/tests/test_core/test_settings.py
def test_defaults_without_yaml(tmp_path, monkeypatch):
    """空目录也能构造：全默认值（§1.2 纪律）。"""
    s = Settings.load(config_dir=tmp_path)
    assert s.get("rag.top_k") == 8

def test_partial_yaml_override(tmp_path):
    """半份 yaml：只写一项，其余回落。"""
    (tmp_path / "settings.yaml").write_text("rag:\n  top_k: 3\n", encoding="utf-8")
    assert Settings.load(config_dir=tmp_path).get("rag.top_k") == 3

def test_env_beats_yaml(tmp_path, monkeypatch):
    monkeypatch.setenv("AGENT_GODOT__rag__top_k", "5")
    (tmp_path / "settings.yaml").write_text("rag:\n  top_k: 3\n", encoding="utf-8")
    assert Settings.load(config_dir=tmp_path).get("rag.top_k") == 5

def test_prompt_fallback_and_render(tmp_path):
    s = Settings.load(config_dir=tmp_path)
    out = s.prompt("permission", "confirm_write", path="res://a.gd", risk="medium")
    assert "res://a.gd" in out            # 默认模板渲染成功

def test_prompt_missing_var_keeps_placeholder(tmp_path):
    (tmp_path / "prompts.yaml").write_text(
        "permission:\n  confirm_write: '写 {path}'\n", encoding="utf-8")
    s = Settings.load(config_dir=tmp_path)
    assert "{path}" in s.prompt("permission", "confirm_write")  # 不崩
```

## 8. 面试拷打（附参考答案）

**1. 为什么 prompt 要外置到 yaml 而不是 Python 常量？**
答：调 prompt 是**运营动作**（改完想立即试），改代码是**工程动作**（要走 lint/test/commit/重启全流程）。外置后：①非开发者（产品/测试）也能调；②调优实验不污染 git 历史（yaml 可 gitignore 本地副本）；③同一份代码服务不同"人设"（多租户各自一份 prompts）。但默认值必须留在代码（§1.2）——保证克隆即跑、yaml 是增强不是依赖。

**2. 三层配置 env > yaml > 默认值，为什么不干脆全用环境变量（12-Factor）？**
答：12-Factor 面向**无状态容器**，env 适合部署期差异（密钥/端口/DB 地址）。但本项目 prompt 模板动辄几十行多行文本、层级深——塞进 env 是灾难（转义/长度/可读性）。混合策略：**env 管"部署期"，yaml 管"运营期"，代码管"出厂值"**——各层管各自生命周期内最自然的载体。

**3. 配置项散在多个 yaml 文件，会不会配置面失控？**
答：用**目录即边界**防：config/ 下一个文件一个职责（models=谁、settings=怎么跑、prompts=怎么说、mcp/permissions=安全），且 settings.yaml 的节名必须与模块名对齐（rag/query_engine/memory…）——看 yaml 就能反推架构图。再加两条纪律：新配置项必须先在 Settings dataclass 声明（带默认值）才能被 yaml 消费（白名单制，防野键）；`godot-agent config` 命令可打印全量生效值与来源层。

**4. 删掉 prompts.yaml 系统还能跑，这为什么重要？**
答：这是**配置与代码解耦的可逆性检验**——外置化最大的风险是"配置成了隐形依赖"（yaml 被误删/合并冲突坏掉，系统整体瘫痪）。默认值兜底保证：①新用户克隆即跑；②yaml 损坏时降级而非宕机（配合启动 warning 日志）；③CI 不需要维护测试配置。反过来，若某配置项没有合理默认值（如必填的 DB 地址），它就属于 L1（env）而不是 L2——分层判断的试金石。

**5. 热加载为什么本期不做？**
答：成本收益比：热加载要解决**会话撕裂**（M00 §12 Q9 三件套：版本快照/引用计数/变更通知）——为"改个 prompt 免重启"引入这套复杂度，在 CLI 为主的产品阶段不值。等 M19 Web 平台上线、配置由管理界面编辑时，再按 models.yaml 已验证的方案接入。**架构演进原则：需求没到，能力不做**。
